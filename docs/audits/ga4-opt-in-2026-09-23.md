# GA4 opt-in implementation review — 2026-09-23

The user supplied the web-stream Measurement ID `G-SY6PZPX0VR` and selected basic consent: Google analytics code must not load until a visitor explicitly allows it. The new WordPress theme uses that ID only when its home URL and the current HTTPS request both use the indexable production host `tio2products.com`. Private previews, alternate hostnames and noindex mode do not render the analytics choice or load a Google tag.

The first-visit panel offers Allow and Reject. The choice is stored in `tio2_analytics_consent_v1` Local Storage. Footer Cookie Settings lets visitors change it later. Acceptance queues a denied default, then analytics-granted consent with advertising consent denied, and then loads GA4. Page and referrer URLs sent by the site's configuration omit query strings and fragments. Withdrawal denies analytics, clears accessible GA4 Cookies and reloads without the tag; an already-denied choice also cleans leftover GA4 Cookies on later visits.

The English Cookie Policy and English/Malay Privacy Policy seeds disclose this conditional behavior. `scripts/migrate-analytics-policy.php` applies only exact reviewed passages on owned Pages and preserves other editor text. Its read-only dry run passed against three Pages in the isolated 18080 preview. The preview database was not modified for the policy test.

Validation performed: `tests/analytics-consent-browser.py` passed four network, storage and Malay-status flows; `tests/analytics-config.php` passed production-host gating; `tests/utility-seeds.py` passed bilingual seed checks; PHP and JavaScript syntax checks passed. The actual footer template was rendered to a browser fixture and visually checked at 1440px, 768px and 390px for the first-visit panel and Cookie Settings dialog. Screenshots are retained in ignored `.local/ga4-consent-*.png` and `.local/ga4-settings-*.png`.
