# M-350 WordPress Build Brief

日期：2026-09-21。用途：全新 WordPress 的产品内容模型与首个产品详情模板开发输入。
本 Brief 直接继承原项目批准内容与标准，不重新审查产品事实、不重写英文文案。用户随后批准实施，执行与 Review 结果记在文末。

## 1. 页面与实现范围

- Page ID：`GRADE-M350`；产品：`M-350`；语言：英文。
- 路径：`/products/m-350/`；面包屑：`Home > Products > M-350`。
- 目的：帮助采购与技术人员评估 M-350，并进入询价、样品、资料申请流程。
- 使用独立 `product` CPT 和共用 Product Detail 模板；产品模型由小型业务插件维护，模板与样式由 Theme 维护。
- `/products/` 使用产品归档模板承载列表，不另建同路径 Page；工艺页面保留其批准路径，实施时验证与产品路由不冲突。
- 全新建立 WordPress 内容记录、模板和共享组件；不导入旧站代码、数据库或配置。原视觉 HTML 仅作设计参考。
- 不引入 Next.js、Headless、多站 scope 运行框架、Page Registry Runtime 或旧 Gate 调度机制。

## 2. 产品字段映射

| WordPress 存储 | 内容与 M-350 初始输入 | 使用位置 |
|---|---|---|
| `post_title` / `post_name` | `M-350` / `m-350` | 后台、列表、URL；不以短标题替代完整 H1 |
| `post_excerpt` | 原 Full Copy §2.1 第一段，原文导入 | 列表摘要、Hero 首段、Product description；同一内容源 |
| 产品文案字段组 | H1、分类标签、Hero 后两段、三项摘要；定位标题/正文/六项事实；应用卡片；两组配方评估；各模块标题、说明、CTA 标签 | 按 Full Copy §2 原文和顺序导入；不同时维护另一份重复 `post_content` 正文 |
| `technical_rows` 有序字段组 | 15 行；每行保存 `property`、`standard`、`typical_value` 原始字符串 | 可见参数表和 Product Schema 同源；保留单位、≥、≤、范围及 `—`，不转成单个数值 |
| `product_application` 分类关系 | Coatings、Printing Inks、Plastics、Paper | 产品列表筛选及应用链接；不默认生成可索引分类归档页 |
| 应用说明字段 | Decorative、Industrial、Automotive Coatings、Printing Inks、Plastics 五个方向；Paper 单独限定段落 | 详细应用文案与大类关系分开；前三个方向都归 Coatings，不增建三个全站分类 |
| `product_process` 分类关系 | Chloride | 工艺标签及关联；不默认生成新的工艺 URL |
| 参数及关系的内部来源说明 | 引用 TDS、批准文案、关系矩阵；参数/关系停用时同步停用对应输出 | 后台可追溯，不显示给买家；缺字段不能自动判定事实被撤销 |
| 特色图片 | 初始留空，源资料无批准型号实物图 | 使用批准的数据/评估视觉；不生成假包装、工厂或发货图片 |
| SEO 字段 | 见 §4 | 由一个输出入口生成，避免 Theme 与 SEO 插件重复输出 |
| 全站目标页面关联 | RFQ、Sample、Documents、Application、Process、Market 页面 | 通过 WordPress 页面关联取得链接；不在每个产品复制一份 URL 配置 |

产品正文与参数在后台可编辑，保存执行权限、类型、允许标记及输出转义检查。初次导入使用批准值；后续部署不得覆盖编辑后的数据。第二个型号使用独立数据，不继承 M-350 的参数默认值。

参数不另加 TDS 没有的测试方法列。内部来源版本不写入可见正文、公共元数据或 JSON-LD。完整正文直接引用 [Full Copy][copy]，不在本 Brief 再复制一套。

## 3. 模板模块与显示规则

| 顺序 | 模块 | 原文位置 / 实现要求 |
|---:|---|---|
| 1 | 共享 Header、面包屑 | Products 为当前导航；全站共用组件 |
| 2 | Product Hero | Full Copy §2.1：一个完整 H1、三段正文、Quote/Sample、三项数据摘要 |
| 3 | Product Positioning | §2.2：正文、六项事实、工艺链接 |
| 4 | Application Directions | §2.3：五个方向，之后单列 Additional Paper Evaluation Path |
| 5 | Formulation Evaluation | §2.4：两组评估内容及非保证说明 |
| 6 | Typical Technical Data | §2.5：Property / Standard / Typical Value 三列、15 行、非规格保证说明及 TDS 申请入口 |
| 7 | Document Request | §2.6：接收页面可用时展示，不承诺所有资料均适用或可提供 |
| 8 | Market Support | §2.7：EU、UK、India、Brazil；保留不代表注册、合规、库存或当地供货的说明 |
| 9 | Sample Request | §2.8：接收页面可用时展示；提交不等于样品、运费或发货获批 |
| 10 | 共享 Footer / 适用的 Cookie Settings | 全站共用，产品页不另建一套 |

产品页末尾不嵌入 RFQ 表单。不增加 FAQ、Related Grades、Origin Support、Not Recommended 或对比模块。应用关系中不添加 Masterbatch / Specialty Materials；Paper 不升级为 TDS 支持的性能承诺。

视觉采用 [Freeze 02][visual] 及其 [批准记录][visual-approval]，不回退至早期 M-350 V0.5。遵循 [Visual Standard][brand] 与 [CTA 增补][cta]: Inter、深蓝/青绿/浅中性色、克制边框和留白；浅色背景功能青绿为 `#008078`；深色资料区说明文字保留修正色 `#d4e0eb`。在真实 WordPress 中实现，不再制作独立原型网站。

## 4. SEO 与动作

- Primary Keyword：`M-350 titanium dioxide`。
- Title：`M-350 Titanium Dioxide for Coatings and Inks | TiO2 Malaysia`。
- H1：`M-350 Titanium Dioxide for Multi-Application Evaluation`。
- Meta：`Evaluate M-350 titanium dioxide for coatings, printing inks and plastics. Review application directions, formulation priorities and 15-row technical data.`
- 原批准生产 canonical：`https://tio2products.com/products/m-350/`。保留为发布配置依据；本地使用 `http://localhost:8080/products/m-350/`，维持禁止索引、不进 sitemap；正式域名切换在 RELEASE 处理，不写死在模板中。
- Product + BreadcrumbList 使用与可见内容相同的数据。技术属性完整表达 Standard 和 Typical Value；不输出 Offer、价格、库存、评分、评论、原产地、制造商、认证、FAQPage 或 QAPage。

| 动作 | 目标路径 | 上下文 |
|---|---|---|
| Hero Quote | `/request-a-quote/` | `grade=M-350`、`source_page=GRADE-M350` |
| Hero / Sample 模块 | `/request-sample/` | 同上 |
| TDS / Documents | `/request-documents/` | 同上；TDS 动作另带 `requested_type=TDS` |
| 共享固定 RFQ | `/request-a-quote/` | 干净路径，不带产品上下文 |

原动作合同中的 `site_scope=tio2-my` 可保留为兼容参数，但不建立多站隔离系统，不把查询参数当授权。RFQ 接收后显示 `Request a Quote for M-350`，引导填写目的地、数量范围、应用和采购要求。价格、库存、MOQ、交付等不作未经批准的承诺。

接收页面未完成时，按原标准省略对应产品 CTA；Sample/Documents 同时省略完整模块。不留下空标题、空卡片或假成功提示。共享固定 RFQ 按共享标准保留，其目标不可用则整体验收/发布未就绪。Application/Process 文案可保留，未完成目标不生成死链接；Market 仅省略不可用目标。全部原目标路径参见 [来源交付资料 §5][handoff]，不自动创建额外页面或承接旧站实现。
